# 八强前瞻：淘汰赛预测页与首页切换（2026-08-16）

## 背景

2026-08-16，TI15 小组赛全部结束：瑞士轮 5 轮 39 场 + 附加淘汰轮 5 场，共 44 场系列赛全部打完，
Liquipedia 已公布主赛事（8/20–8/23）的完整对阵表。**站点此前所有页面都是回头看的**
（结论、复盘、抄作业都在讲已经发生的事），而读者现在最想要的是**往前看**：接下来这 14 场怎么打。

本设计只解决一件事：**把「剩下的比赛会怎样」做成站点的第一落点。**

已完赛结果、附加轮、八强对阵的录入与条件化由并行会话完成
（`model/results.json` 的 `rounds` / `elimination` / `playoffs.ubqf`，
`model/l2_simulate.py` 的 `seeds_from_ubqf`），本设计不重复这部分。

## 三个设计决定

### 决定一：用精确枚举替代蒙特卡洛

8 队双败共 14 场，实质路径 8192 条，**可以穷举**。枚举给出的是精确概率，没有抽样噪声；
实测 0.3 秒（含对实力不确定性抽 6000 次后平均），比 20 万次蒙特卡洛又快又准。

实力不确定性仍按项目既有方法论传播：对 θ ~ N(θ̂, se) 重抽，每次做一遍精确枚举再平均——
这一点与 `l2_simulate` 一致，不引入新的方法论分歧。

新模块 `model/l6_playoffs.py`，产出 `reports/p8_playoffs.json`。
`model/bracket.py` 与 `model/l2_simulate.py` **一行不改**（它们仍是全赛事口径的主链路，
本模块只做「小组赛已结束」这一特定条件下的前瞻，两者的冠军概率必须互相吻合，
`tests/test_l6_playoffs.py` 把这条吻合钉成断言）。

### 决定二：反解「隐含实力」，让整页数字出自同一套参数

问题：市场只开夺冠盘，没有「谁进四强」「QF 谁赢」的盘口。若冠军概率用融合值、
逐场胜率用纯模型值，同一页里两组数字来自两套参数，互相对不上——
读者按逐场胜率自己乘一遍，得不到页面上的冠军概率。

做法：反解一组隐含实力 θ*，使枚举出的冠军概率**恰好等于**
`model/l2_blended.json` 里的融合值（模型 ⊕ 市场，市场权重 0.7），
然后逐场胜率、各轮晋级、名次分布**全部从 θ\* 读出**。

**这个反解是恰好可辨识的，不是拟合**：8 支队的概率和为 1 → 7 个独立目标；
θ* 有 8 个分量、锚定均值后 7 个自由度。恰好定解，不存在过参数化或欠定。
不动点迭代（θ*ᵢ += 0.45·[logit(目标ᵢ) − logit(当前ᵢ)]），实测 82 轮收敛到 2e-4。

**明确的局限**（要写在页面上）：这一步假定「融合后的冠军分布是由某组 BT 实力
经这套赛制生成的」。市场若因为赛制之外的理由（阵容伤病、签表软硬的主观判断）
给某队定价，反解会把那部分理由**强行翻译成实力**。所以隐含实力是
「市场若只通过实力表达观点，它在说什么」，不是「这支队真实有多强」。

### 决定三：把「模型看不到 TI15」这件事量化，而不是辩解

模型的实力分训练截止 2026-08-02，**没有见过 TI15 任何一局**。
最刺眼的后果是 Nigma Galaxy：瑞士轮 4-1 直通八强，模型只给 1.2% 夺冠，市场给 7.9%。
读者的第一反应必然是「你数据没更新」。

所以本版把这条质疑正面堵死：用赛前后验 N(θ̂, se) 当先验，把 TI15 这 109 局做贝叶斯更新，
看实力分该挪多少。**实测结果是几乎不动**——最大位移 ±0.095（OG −0.095、HULIGANI −0.086、
Nigma +0.074），Nigma 从 +0.374 升到 +0.448，仍是 16 队里倒数第五；
重算冠军概率后最大位移 **1.5pp**（VISION 22.5→23.9、Yandex 14.2→12.9、Nigma 1.1→1.5）。

原因是先验太紧：Nigma 赛前 se=0.145（先验精度 47.6），10 局证据的费雪信息约 2.5，被 19:1 压住。

⇒ **模型与市场的分歧不是「数据没更新」造成的，折进 TI15 战绩之后依然存在。**
这是个能量化、能写、且赛后可判对错的点，比含糊地说「模型有局限」有用得多。

诚实的限定（页面上要写）：这个更新把「赛前实力到今天仍然有效」当成前提，
没有为状态漂移放宽先验方差，所以它给出的是「TI15 战绩该挪多少」的**下界**。

## 产出物

`reports/p8_playoffs.json`：

| 字段 | 内容 |
|---|---|
| `ubqf` | 四场八强对阵与开赛时间 |
| `views.model` / `views.blended` / `views.updated` | 三套口径，各含 `place`（名次分布）、`stage_pairs`（各阶段对阵概率）、`h2h`（存活八队两两 BO3 胜率） |
| `theta` / `theta_implied` / `theta_updated` | 三组实力分 |
| `market` | Polymarket 中间价与归一化后的隐含概率 |
| `robustness` | 贝叶斯更新诊断的逐队位移与概率位移 |

## 页面

新建 `site/playoffs.py`，渲染为 **`index.html`（首页）**；
原「结论」页迁到 `overview.html`，导航保留入口，内容不动。
首页 URL 不变（`shadowjacob.shop/dota2/`），外链不失效。

页面结构（自上而下）：
1. **四场八强**：对阵卡片，各含融合胜率、模型胜率、开赛时间
2. **夺冠概率**：融合 / 模型 / 市场三列并排，分歧最大的两支高亮
3. **模型和市场在哪儿吵架**：Falcons 与 Nigma 两个案例 + 贝叶斯稳健性结论
4. **完整名次分布**：8 队 × 8 个名次
5. **下一轮最可能是谁打谁**：各阶段对阵概率前几名
6. **这版预测的三条局限**：隐含实力的翻译问题、模型没见过 TI15、单场样本极少

## 抄作业页的处理

小组赛那 16 格**已全部揭晓**，`record_dist` 退化成 0/1，`solve()` 会直接给出标准答案、
期望答对数变成 16——页面若照旧渲染，会变成一句毫无意义的「我们建议你填正确答案」。

改法：检测到已揭晓（各档概率非 0 即 1）时切换措辞，改为
**公布标准答案 + 用赛前冻结件给自己打分**（`frozen/frozen_v9-postdraw-predictions.json`
是 8/13 锁定前挂在站上的那一版，逐格比对答对了几格），
并把梦幻挑战与仍然开放的主赛事部分留在原位。
